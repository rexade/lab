# Run 095

## Run 95 — 2026-07-03 — RESEARCH

**What I investigated:** The four incubator-loop threads against the live system: where AI-feedback parsing lives (ProjectPanel.jsx vs AiPanel.jsx vs server), what the codex runner's preflight failures leave behind, how much failure detail the runs API ships, and whether the JSON API boundary holds live (it does — verified `/api/*` 404 returns JSON).
**Key finding:** Preflight failures are invisible: run-codex-incubator.sh exits 127 (no codex binary) or 1 (missing prompt) *before* its first write to RUN_LOG (line ~104), and server.js spawns all runs with `stdio: 'ignore'` — so a preflight-stage failure produces no FAILED entry, no stderr, nothing; the run silently never happens. All artifacts exist today (codex symlink, run-*.sh, prompt files), so the bug is latent but unguarded. Secondary: `parseAnalysis` is duplicated (full version ProjectPanel.jsx:23 with malformed detection, degraded copy AiPanel.jsx:12 without it), and it's pure string ops — directly portable to server.js which already owns the DRIFT_FEEDBACK.json write path.
**Implication:** The next build run can close both gaps cheaply: (1) parse fields/missing/malformed server-side at analyze time, store them in DRIFT_FEEDBACK.json, compute on read for legacy files — AiPanel then deletes its parser; (2) add `GET /api/incubators/:id/preflight` (script exists, binary executable, prompt file present, status.json parses) surfaced next to the RUN button, plus make the script trap preflight exits and append a `[run failed — preflight]` block so nothing dies silently. Also found in the same fallthrough family as the seed's JSON bug: `POST /api/incubators` replies `restarting: true` (server.js:950) but never restarts, while static play routes only mount at startup (server.js:785) — a slot added at runtime gets a playUrl that serves the pi-pulse SPA instead of the project until manual restart.
**Suggested next move:** MUTATE: move `parseAnalysis` into server.js (shared by analyze + latest endpoints, both /api/incubators/:id/ai/* and legacy /api/ai/*), add the preflight endpoint + script-side preflight logging, and either actually restart on incubator add or register play routes dynamically. Failure-detail bonus: parseStdoutRunBlocks already holds the full failed body in scope — ship a capped `detail` field for FAILED runs so the UI can make the 92-char summary expandable.
