## Run 134 — 2026-07-04 — RESEARCH

**What I investigated:** Seed-aligned trust failures around newly created incubators: runner switching to Claude, stale `fable` handling, available runner scripts, current project status files, child run logs, formal run-log parsing, API/SPA fallback guards, and the existing `test:trust` harness.
**Key finding:** The new incubators do have useful run-log paragraphs, but `parseFormalRunBlocks` only extracts `**Field:** value` lines, so paragraph-only `## Run` blocks return number/date with no summary and the UI falls back to `stdout captured with no summary`. Separately, newly created incubators cannot switch to Claude because no `/home/admin/run-<slug>.sh`, `claudeModel`, `CLAUDE_MODEL`, or `DEFAULT_CLAUDE_MODEL` exists for them.
**Implication:** The next build should not add features; it should make existing runs judgeable. Fixing formal run parsing will immediately make current child histories readable, and runner switching should explain the missing Claude script/model as a setup requirement rather than appearing broken.
**Suggested next move:** MUTATE: add parser support for paragraph-style formal run blocks by using the first meaningful paragraph as a summary when no bold fields exist, normalize lowercase run types to CREATE/MUTATE/RESEARCH, fixture it with the pirate and sawbuck log shapes, then surface the exact `no Claude runner script` / `missing Claude model` switch error beside the selected incubator.
