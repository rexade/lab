## Run 98 — 2026-07-03 — RESEARCH

**What I investigated:** Seed-aligned Pi Pulse incubator reliability: current server run spawning/capture, stdout FAILED parsing, incubator play-route/API fallthrough boundaries, ProjectPanel run handling, live incubator status, and runner scripts/default models.
**Key finding:** The old invisible-preflight hole is partly fixed in source: `spawnTrackedRun` now captures child stderr/stdout and appends a server-captured FAILED block on non-zero exit, and `POST /api/incubators` now mounts project play routes dynamically. The next real weakness is runner readiness: there is still no preflight/readiness API, the UI ignores failed launch responses, and the Claude path still defaults to invalid `fable` in `run-lab.sh`, `run-race-whisperer.sh`, `run-taste-trainer.sh`, and `updateProjectRunner`; race-whisperer is currently configured with `runner: "claude"` plus `claudeModel: "fable"`, matching the repeated model-access failures in run 95.
**Implication:** The next build should stop treating run launch as fire-and-forget. Pi Pulse can now record many early failures after spawn, but users still cannot see before clicking whether a slot has a missing prompt, missing repo, unsupported runner, or known-bad model. A preflight endpoint can also keep scheduled runs from burning cycles on predictable failures.
**Suggested next move:** MUTATE: add `GET /api/incubators/:id/preflight` and host `/api/run/preflight`, returning checks for status JSON parse, repo dir, runScript, runLog dir, promptDir/current prompt, binary availability, and model config; render a compact readiness/error row near the runner switch/run button; make `runProjectSlot` inspect non-OK responses; remove `fable` as the default Claude model or force affected slots back to Codex until a valid Claude model is selected.
