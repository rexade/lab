# Run 003

## Run 3 — 2026-04-08 — RESEARCH

**What I investigated:** Three areas aligned with the "single beautiful instrument" seed: (1) best React pattern for globally shifting `--accent` CSS var based on live stats, (2) whether Catmull-Rom splines would visibly improve the waveform over the current quadratic bezier, (3) premium design patterns for a sparse RunHistory and the lower half in general.

**Key finding:** The lower half architecture is the core problem. The current 2-column card grid (RunHistory + ControlCluster as siblings) is structurally what makes Pi Pulse feel like a "dashboard of parts." The fix is a unified surface: one panel that contains both as sections separated by hairline borders, not separate floating cards. Hardware console UIs (Teenage Engineering, Raycast, Vercel) never use floating card grids — they use one faceplate with logical zones.

**Implication:** Three concrete upgrades are now research-validated with clear implementation paths: (1) Ambient color mode via `document.documentElement.style.setProperty` — safe in React 18, zero re-renders, needs `@property --accent { syntax: '<color>' }` in CSS for smooth color interpolation rather than hard snapping. (2) Catmull-Rom waveform — formula is `B1 = P1 + (P2-P0)/6`, `B2 = P2 - (P3-P1)/6` — visibly smoother C2 continuity vs current C1 quadratic, implementable without adding d3 as a dep. (3) RunHistory as vertical timeline (left-edge accent line + circular type nodes) instead of stacked cards — looks intentional with 2 items, looks rich with 4.

**Suggested next move:** MUTATE run should tackle the structural issue first: collapse RunHistory + ControlCluster into one unified lower panel, convert RunHistory to a vertical timeline with glowing nodes, and add `@property --accent` + ambient color shift in App.jsx based on CPU/temp threshold.
