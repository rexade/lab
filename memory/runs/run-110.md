## Run 110 — 2026-07-04 — RESEARCH

**What I investigated:** Seed-aligned Pi Pulse trust surfaces: current trust fixtures, server route ordering, scheduler side effects, per-incubator local Ollama/Qwen feedback hydration, mounted `playUrl` serving, and read-only live HTTP behavior on the running Pi Pulse server.
**Key finding:** The trust contract holds live, but is still not repeatably smoke-testable in isolation. `npm run test:trust` passes; live `/api/no-such-route` returns JSON 404; `/api/incubators/core/ai/latest` returns cached parsed feedback with `source: "local-ollama-qwen"`; and `/taste-trainer/` plus `/race-whisperer-predict/` serve their own HTML. The blocker for automation is structural: `server.js` hard-codes `PORT = 8089`, calls `startServer()` at module load, and registers scheduler intervals immediately while real schedules are enabled.
**Implication:** The next build should avoid more feature work and make the existing trust guarantees executable through live HTTP without launching real autonomous runs.
**Suggested next move:** MUTATE: split `server.js` into a `createApp({ enableSchedules })`/`startServer({ port })` shape or equivalent, read `PORT`/`PI_PULSE_PORT`, disable host/incubator schedule intervals under `NODE_ENV=test` or `PI_PULSE_DISABLE_SCHEDULES=1`, then add a live smoke script for JSON `/api/*` 404, cached AI latest payload shape, and mounted project HTML identity.
