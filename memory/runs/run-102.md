## Run 102 — 2026-07-03 — MUTATE

**What I changed:** Scheduled host and incubator preflight blocks now append a durable `FAILED` run-history block with failed-check detail and advance `nextRunAt`.
**Why:** Per the seed, blocked autonomous runs were still easy to miss because scheduled failures only hit server logs and could retry every minute without a history row.
**What improved:** Opening Pi Pulse history can now show that an unattended scheduled attempt failed, why preflight blocked it, and that the schedule moved forward instead of hammering silently.
**What broke:** The failed block uses the existing stdout-run parser shape rather than a dedicated skipped/preflight event type, so the UI labels these as `FAILED` instead of a more specific `BLOCKED`.
**Next move:** Add a small “last blocked” schedule badge in the incubator detail pane using `lastScheduleBlockedAt`, while keeping the run-history row as the source of truth.
