# Run 020

## Run 20 — 2026-04-08 — CREATE

**What I built:** Server-side project status auto-sync (`syncProjectStatus` in `server.js`) and persistent "lab running" visual state on the Run Lab button in `BottomPanel.jsx`
**Why this direction:** Active thread: `projects/pi-pulse/status.json` had hardcoded `runCount: 11` (was at 20). The thread said to close this with a server endpoint. Extended to also surface the run state in the UI — the Run Lab button had no persistent feedback while a session was in flight.
**What's interesting:** `syncProjectStatus()` hooks into the existing `fs.watch(RUN_LOG_PATH)` so status.json stays current automatically — zero API calls required. The "lab session running" state on the button persists (with slow-spinning loader + pulsing accent dot + stronger glow) until the SSE stream fires a new run update, then clears. The button now tells you when the system is actually working, not just for 900ms after clicking.
**What got worse:** The "run in flight" detection relies on run number increasing — if a run completes without changing the latest run number (e.g., re-run of same session), the indicator won't clear until the next poll.
**Next move:** Visual language stress test — harden edge states: Pi unreachable (no-stats), very long DIRECTION text overflow in AI zone header, mobile single-column layout. Confirm all look premium before expanding the project incubator.
