## Run 41 — 2026-04-09 — MUTATE

**What I changed:** Added defense-in-depth text sanitization to `server.js` `/api/narration` endpoint — strips multi-line LLM output before it reaches the browser.
**Why:** The NarratorVoice zone was fully wired but the API endpoint served raw JSONL text with no sanitization. If narrator outputs multi-line text (as it did in all 50 stored narrations before its service restart), the voice inscription would render the full multi-line string including AI disclaimers. narrator.js had the fix, the endpoint did not.
**What improved:** `server.js:563` now applies `.split('\n')[0].trim().slice(0, 100)` to the text field before the JSON response. Even if narrator.service generates messy output, the browser always sees one clean line. Defense-in-depth: both layers sanitize independently.
**What broke:** Nothing. No build needed (server.js is Node). Requires `sudo systemctl restart pi-pulse` to activate — and `sudo systemctl restart narrator` to activate the Run 37+39 narrator.js changes that are still running old code.
